Detailed Description

Manages the server’s fixed-timestep update loop.

The ServerClock is responsible for maintaining a stable tick rate (_hz), using high-resolution time measurements and synchronization primitives to delay updates until the correct time interval has passed.

This ensures deterministic and reproducible simulations across clients and server instances, which is critical for real-time multiplayer synchronization.

Parameters
hzThe desired tick rate (in Hertz). Default is 60 Hz.

The clock starts in an idle state. Call start() to begin the tick cycle. The hz parameter determines the number of updates per second, which directly affects the simulation frequency and CPU usage.

void ServerClock::waitNextTick ( )

Waits for the next tick to occur.

Blocks the calling thread until the next tick is due, ensuring that updates happen at consistent intervals according to _hz.

Commonly used in the main loop:
