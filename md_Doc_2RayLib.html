Why We Chose Raylib for the Game Rendering and Input System

1. Introduction

In our R-Type project, we selected raylib as the main multimedia and rendering library. The primary goal behind this choice was to have a simple, efficient, and cross-platform solution to handle graphical display, user input, audio, and resource management.

Raylib is a lightweight, open-source C library designed specifically for learning, rapid prototyping, and small to mid-scale game projects. It provides a clean, minimal, and intuitive API that allows developers to focus on game logic rather than graphics engine complexity. This makes it particularly well-suited for an educational project like R-Type, which emphasizes real-time systems, modularity, and clarity of design.

2. Why raylib?

2.1 Simplicity and Readability

Unlike heavier frameworks such as SDL, SFML, or raw OpenGL, raylib provides an extremely clean and easy-to-understand API. Its primary design philosophy is "learn by doing" — giving developers direct access to graphics and input functions without excessive boilerplate code.

Example:

InitWindow(800, 600, "R-Type");
while (!WindowShouldClose()) {
BeginDrawing();
ClearBackground(BLACK);
DrawText("Hello R-Type!", 300, 280, 20, RAYWHITE);
EndDrawing();
}
CloseWindow();

This small snippet demonstrates a fully functional rendering loop, ready to integrate into our ECS engine. The clarity and compactness of raylib’s API significantly accelerate development and debugging.

2.2 Cross-Platform Portability

Raylib runs seamlessly on Windows, Linux, macOS, and even the Web (via WebAssembly). This ensures that the game can be built and tested on multiple platforms without any code changes — an essential feature in a multi-environment academic setting such as Epitech.

The same code compiles everywhere, making our R-Type project both portable and maintainable.

2.3 Easy Integration with C++ and ECS Architecture

Although raylib is written in C, it is fully compatible with C++, making integration into our Entity-Component-System (ECS) straightforward. Each entity with a position_attr_t or render_attr_t component can directly use raylib’s drawing functions.

Raylib acts as the rendering and input layer, while our ECS engine manages game logic, entities, and updates. This separation of responsibilities keeps the architecture clean, modular, and scalable.

2.4 Built-in Multimedia Management

Raylib includes native support for all essential multimedia tasks:

  • Loading and drawing textures (PNG, JPG, BMP, etc.)
  • Playing sounds and music (WAV, OGG, MP3)
  • Displaying text with custom fonts
  • Handling 3D models and shaders

Because these features are built-in, we avoid the complexity of linking multiple libraries (such as stb_image, OpenAL, or FreeType) manually. This significantly simplifies dependency management and reduces project setup time.

2.5 Performance and Lightweight Design

Despite its simplicity, raylib is built on top of OpenGL, which ensures excellent rendering performance even on modest hardware. It supports static compilation, resulting in very lightweight executables with minimal startup time.

This design provides:

  • Low display latency
  • Smooth framerate
  • Fast initialization and teardown

In a fast-paced game like R-Type, where timing precision is crucial, this efficiency is a major advantage.

2.6 Comparison with Other Libraries

Alternative Main Drawbacks
SDL2 Verbose API; requires multiple modules (SDL_image, SDL_mixer, SDL_ttf).
SFML More C++-oriented but heavier and less suited for a modular ECS engine.
OpenGL (raw) Too low-level; requires manual management of shaders, buffers, and matrices.
Unity / Unreal Engine Overkill for an academic project; large, closed environments not suited for low-level C++ control.
Raylib Lightweight, open-source, portable, and simple to integrate with custom ECS logic.

3. Benefits for the R-Type Project

Raylib offers multiple advantages that align perfectly with our project requirements:

  • Fast development and iteration due to a minimal API.
  • Seamless integration into our ECS-driven engine.
  • Cross-platform compatibility (Windows/Linux tested successfully).
  • No heavy dependencies or external configuration required.
  • Excellent documentation and examples, reducing the learning curve.

Additionally, raylib provides useful complementary tools such as:

  • rres for embedded resource management.
  • raygui for lightweight graphical interfaces.
  • raudio for sound and music playback.

These features make raylib an all-in-one framework for small-to-medium games built in C/C++.

4. Conclusion

We chose raylib because it offers the best balance between simplicity, performance, and flexibility for a lightweight, modular game engine. Its straightforward API, strong portability, and efficient OpenGL-based rendering make it ideal for developing R-Type’s visual layer and player interaction system.

By using raylib, we can focus our efforts on game logic, networking, and ECS architecture instead of low-level rendering details. In short, raylib is not just a graphics library — it’s a complete, educational, and modern framework that perfectly fits the spirit of a technical, performance-oriented project like R-Type.
