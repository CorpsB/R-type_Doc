8/**
9 * @file AudioManager.hpp
10 * @brief High-level manager for engine audio playback and caching.
11 * @since 0.1
12 * @ingroup audio
13 *
14 * @details
15 * The `AudioManager` provides the main interface between gameplay systems
16 * and the underlying `AudioDriver`. It is responsible for:
17 * - managing all sound entries (creation, destruction, caching),
18 * - forwarding playback and volume control to the selected driver,
19 * - interacting with the engine’s storage system to load sounds on demand,
20 * - exposing a unified API through the `IAudio` interface used by scripts,
21 * world logic, and the engine core.
22 *
23 * The manager uses a thread-safe cache to avoid reloading the same sound
24 * multiple times, limiting the cache size via `MAX_CACHE_SOUNDS`.
25 *
26 * Implementations of `AudioDriver` (such as @ref asge::audio::RaylibDriver or
27 * @ref asge::audio::NullAudio) handle the actual low-level playback.
28 *
29 * @see IAudio, AudioDriver, RaylibDriver, NullAudio
30 */
31

49/**
50 * @class AudioManager
51 * @brief High-level audio control system for the ASGE engine.
52 *
53 * @details
54 * The `AudioManager` acts as a bridge between the engine logic (e.g., gameplay code)
55 * and the selected backend `AudioDriver`. It provides a simple, consistent API
56 * for sound playback, caching, and volume control.
57 *
58 * It does not perform decoding itself — all low-level work is delegated to the driver.
59 * However, it manages:
60 * - caching and reuse of loaded sounds,
61 * - on-demand loading from file or memory,
62 * - volume scaling relative to the master volume,
63 * - synchronization between threads using a mutex.
64 *
65 * This class is instantiated by the engine core and accessed through
66 * the global service registry (`asge::Services`).
67 */
